## 二、🔴 严重问题（15 项）

### Rust API

**S1. JS 沙箱仍可被 `eval` + 原型链绕过 → RCE**
- `api/nexus-engine/src/legado/selector/js.rs:64` — 用户代码通过 `_origFunction(...)` 执行，虽然 `globalThis.Function` 被覆盖，但：
  - `eval` 仍可用：`eval("this.constructor.constructor('return process')()")` 可重新获取 `process`
  - 原型链不受 `globalThis.Function` 覆盖影响
- fallback 路径（js.rs:224）同样可通过 `eval` 逃逸
- **影响**：Legado 书源可执行任意命令

**S2. SSRF DNS Rebinding — 校验与请求使用不同 DNS 解析**
- `api/nexus-core/src/url_safety.rs:42-55` 和 `api/nexus-server/src/validation.rs:58-91` — 先 DNS 解析检查 IP，然后发起请求时 reqwest 重新解析 DNS
- 攻击者配置 TTL=0 的 DNS，校验时返回公网 IP，请求时返回 `127.0.0.1`
- **影响**：绕过所有 SSRF 检查

**S3. 内容抓取路径未禁用 HTTP 重定向 → 重定向 SSRF**
- `api/nexus-engine/src/fetcher/client.rs:41-52,76-89` — `HttpFetcher` 的 `Client::builder()` 未设 `.redirect(Policy::none())`
- `api/nexus-engine/src/anti_crawl/strategies.rs:78,102,158,540` — 所有 anti_crawl strategy 同样未禁用重定向
- reqwest 默认跟随最多 10 次 3xx 重定向 → SSRF 校验通过后可重定向到内网
- **对比**：`routes/source.rs:26-33` 的 `URL_IMPORT_CLIENT` 已正确设置 `.redirect(Policy::none())`

**S4. `SafeHtml` 的 `unsafe impl Send` 存在 UB 风险**
- `api/nexus-engine/src/html_doc_cache.rs:20` — `scraper::Html` 内含 `Rc`，强制 Send 后 `get_or_parse` 返回 clone，调用方在 async task 中使用 → 跨线程操作 `Rc` 引用计数

### Web 前端

**S5. 缺少 Content-Security-Policy 头**
- `web/_headers` — 有 `X-Frame-Options`、`X-Content-Type-Options` 等，但无 CSP
- `v-html` + CDN 字体加载（`rsbuild.config.ts:71` 从 `cdn.jsdelivr.net`）扩大 XSS 攻击面

**S6. 无 lockfile 提交**
- `web/` 目录下无 `bun.lockb` 或 `bun.lock` — CI 和各环境依赖版本不可复现

### Edge Worker

**S7. MISCONFIGURED 错误在所有环境泄露后端 URL**
- `edge/entry.ts:40` — `validateWorkerEnv` 抛出的错误含 `NEXUS_API_URL` 实际值，无条件传给客户端
- **对比**：`proxy.ts:202` 正确地只在 `development` 环境传 `details`
- **影响**：攻击者可获取后端 API 真实地址

**S8. 请求体大小限制可通过 chunked 编码绕过**
- `edge/shared/proxy.ts:107-121` — 仅检查 `Content-Length` 头，`Transfer-Encoding: chunked` 时 `contentLength` 为 `null`，限制被跳过
- **影响**：DoS

**S9. `package-lock.json` 名称与 `package.json` 不一致**
- `edge/package.json:2` — `nexus-edge`
- `edge/package-lock.json:3` — `novel-decoder-optimized`（旧项目名）
- **影响**：`npm ci` 严格模式可能失败

### Bypass 服务

**S10. 浏览器引擎 `page.goto` 自动跟随重定向，绕过 SSRF 校验**
- `bypass/engines/browser_probe.py:188,208,257,322,574` — Chromium 默认跟随 3xx，Pydantic 层 IP 校验无效
- 攻击者用公网域名 302 跳转到 `169.254.169.254` → 返回内网内容
- **第一轮已识别但未修复**

**S11. DNS rebinding TOCTOU**
- `bypass/main.py:97-111` — 校验时 DNS 解析检查 IP，请求时引擎重新解析 DNS
- **与 S2 同类问题**

**S12. 安全关键路径零测试**
- `_validate_url_not_private`、`/fetch` 端点、API key 认证、引擎 fetch 行为均无测试
- 第一轮的认证修复和 SSRF 修复都缺少自动化测试守护

### CI/CD 与部署

**S13. `docker-compose.yml` 前端端口映射错误 — 服务无法启动**
- `docker-compose.yml:42` — `"${NEXUS_PORT:-8080}:80"` 映射到容器 80 端口
- `web/nginx.conf:2` — `listen 8080`（第一轮修复改的）
- `web/Dockerfile:14` — `EXPOSE 8080`
- **影响**：`docker compose up` 后 nginx 容器内无进程监听 80 端口

**S14. `.gitignore` 中 `//` 注释行被 git 误识别为路径模式**
- `.gitignore:41` — `    // Allow specific data files for nexus-lite`
- git 只识别 `#` 作为注释，`//` 不是有效注释
- `.gitignore:42` — `!nexus-lite/data/qidian/` 对不存在目录的否定规则

**S15. `.env.example` 和 `docker-compose.yml` 缺少 `CF_API_KEY`**
- `bypass/main.py:28` 依赖 `CF_API_KEY`，未设置时所有 fetch 端点返回 503
- `.env.example` 和 `docker-compose.yml:32-35` 的 bypass environment 均未传递此变量

## 三、🟡 中等问题（精选 Top 15）

### 安全类

1. **API 全局请求体大小无限制** — `api/nexus-server/src/app.rs` 无 `DefaultBodyLimit`，可 OOM
2. **API `import_legado_sources` 接受任意 `serde_json::Value`** — `routes/source.rs:132` 无大小/数量限制
3. **API CORS `allow_methods(Any)` + `allow_headers(Any)`** — `app.rs:147-152`
4. **Edge 无 HTTP 方法白名单** — `dispatch.ts:33-44`，TRACE 等方法穿透
5. **Edge 缓存键不含认证信息** — `proxy.ts:75`，可能缓存投毒
6. **Edge URL 参数双重解码** — `proxy.ts:60-72`，可能绕过后端校验
7. **Bypass 异常字符串原样回传** — `curl_impersonate.py:133` 等，可能泄露内部信息
8. **Bypass CORS `allow_methods=["*"]` + `allow_headers=["*"]`** — `main.py:200-210`
9. **Bypass Chrome 调试端口绑 `0.0.0.0`** — `browser_probe.py:_find_free_port` 用 `s.bind(("", 0))`
10. **Docker Compose 无网络隔离** — frontend 可横向访问 bypass

### 代码质量类

11. **Rust JS Worker 在 async 中持有 `std::sync::Mutex` 执行同步 I/O** — `js.rs:149`，阻塞 tokio 线程最长 10s
12. **Rust `html_doc_cache.rs` 仍用 `std::sync::Mutex`** — `html_doc_cache.rs:22`（第一轮遗漏）
13. **Rust `js.rs:135` JS_WORKER 仍用 `std::sync::Mutex`** — 第一轮遗漏
14. **Web scroll listener 泄漏** — `view-feature-effects.ts:19` 清理函数被丢弃
15. **Web `bootstrap.ts` setInterval 永不清理** — `bootstrap.ts:11-16`

## 五、建议优先级

### P0 — 立即修复

1. **S1 JS 沙箱 eval 绕过** — 覆盖 `eval`，或改用 `vm.runInNewContext`
2. **S3 HTTP 重定向 SSRF** — `HttpFetcher` 和 anti_crawl strategies 添加 `.redirect(Policy::none())`
3. **S10 浏览器 `page.goto` 重定向** — `page.goto` 后检查 `page.url` 是否仍为公网
4. **S13 docker-compose 端口映射** — `:80` 改为 `:8080`
5. **S14 .gitignore `//` 注释** — 删除残留 nexus-lite 规则
6. **S15 缺少 CF_API_KEY** — 补充到 `.env.example` 和 `docker-compose.yml`

### P1 — 近期修复

7. **S4 SafeHtml UB** — 移除 `unsafe impl Send`，改用 `spawn_blocking` 或线程局部缓存
8. **S5 缺少 CSP** — 在 `_headers` 添加 CSP
9. **S7 Edge MISCONFIGURED 泄露** — 仅在 development 环境传 `details`
10. **S8 Edge chunked 绕过** — 实现流式字节计数
11. **S2/S11 DNS rebinding** — pin DNS 解析结果到请求
12. **API 请求体限制** — 添加 `DefaultBodyLimit`
13. **Rust JS Worker Mutex** — 改用 `parking_lot::Mutex` + `spawn_blocking`
14. **补安全模块测试**

### P2 — 中期改进

15. CORS 收紧、网络隔离
16. 死代码清理、lockfile 提交
17. AGENTS.md 更新
18. Actions 锁定 SHA + Dependabot github-actions
