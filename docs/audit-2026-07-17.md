## 二、🔴 严重问题（15 项）

### Rust API

**S1. SSRF：内容抓取路径不检查私有 IP**
- `api/nexus-server/src/routes/book.rs:35` — `validate_url_with_options(url, true)` 的 `allow_private=true` 允许抓取 `127.0.0.1`、`192.168.x.x` 等内网地址
- `api/nexus-engine/src/legado/engine.rs:212-253` — Legado 引擎 `fetch()` 仅检查 scheme，不检查目标 IP
- `api/nexus-server/src/validation.rs:57-75` — `is_private_host` 只做字面量检查，不做 DNS 解析，可被 DNS 重绑定绕过
- **影响**：攻击者可导入恶意 Legado 书源，其 `bookSourceUrl` 指向内网服务，实现 SSRF 探测

**S2. JS 沙箱可逃逸**
- `api/nexus-engine/src/legado/selector/js.rs:28-55` — `_origRequire` 变量仍可被 eval 的代码访问，绕过 `child_process`/`fs` 模块封锁
- `process.env` 未屏蔽 → 泄露服务器环境变量
- `Function` 构造器未屏蔽 → `Function('return process')()` 可绕过
- `execute_via_node_fallback` (js.rs:210-239) 沙箱更弱，仅阻止 `process.exit`/`process.kill`
- **影响**：Legado 书源来自社区不可信，可执行任意代码读取服务器环境变量、访问文件系统

**S3. `HealthTracker` 使用 `std::sync::Mutex` 并在热路径 `expect()`**
- `api/nexus-core/src/health_tracker.rs:217,248,288,294,306,315,322,332` — 8 处 `.lock().expect("health tracker lock")`
- 在每次搜索/内容获取回调中调用（`orchestrator.rs:111,137-138`）
- **影响**：Mutex poison 后整个服务崩溃

**S4. `SafeHtml` 的 `unsafe impl Send` 可能导致 UB**
- `api/nexus-engine/src/html_doc_cache.rs:20` — `scraper::Html` 内含 `Rc` 非线程安全，强制实现 Send
- `get_or_parse` 返回 `Html` clone，调用方在 async task 中使用 → **实际已跨线程使用 Rc**
- **影响**：use-after-free / double-free

**S5. `NodeRunner.build_params` 手动拼接 JSON 字符串**
- `api/nexus-engine/src/script/node.rs:261-267` — 用 `format!` 拼 JSON，存在 JSON 注入风险
- 若 `source_id` 含 `"` 或 `\` 可注入任意 JSON

### Web 前端

**S6. 缺少 Content-Security-Policy 头**
- `web/_headers` 配置了 `X-Frame-Options`、`X-Content-Type-Options` 等，但完全没有 CSP
- `ReaderScrollChapter.vue:33` 使用 `v-html` 渲染内容
- `rsbuild.config.ts:71` 从 `cdn.jsdelivr.net` 加载字体 CSS
- **影响**：DOMPurify 被绕过或 CDN 被劫持时，XSS 攻击面大

**S7. 文件/目录同名冲突 — 模块解析歧义**
- `src/utils/errors/core.ts` 与 `src/utils/errors/core/` 目录同时存在
- `src/utils/errors/processing.ts` 与 `src/utils/errors/processing/` 目录同时存在
- **影响**：不同打包器/TS 版本可能解析不一致

**S8. `_redirects` 硬编码生产 URL**
- `web/_redirects:7` — `/api/*  https://api.nexus-reader.pages.dev/:splat  200`
- 公开仓库暴露后端部署位置

### Edge Worker

**S9. 缓存键不含用户标识，可能跨用户缓存私有数据**
- `edge/shared/cache.ts:34` — 缓存键仅基于 `path + JSON.stringify(params)`
- `edge/entry/dispatch.ts:42` — 对 `/api/book`、`/api/content` 等启用缓存
- **影响**：不同用户请求相同路径可能命中同一缓存，返回错误数据

**S10. 测试覆盖严重不足，核心安全模块无测试**
- 仅 1 个测试文件 `edge/tests/proxy.test.ts`（181 行）
- CORS 白名单、路由白名单、环境校验、缓存逻辑均无测试

### Bypass 服务

**S11. 浏览器引擎 SSRF 防护可被 `page.goto` 绕过**
- `bypass/engines/browser_probe.py:188,208,257,322,574` — `page.goto(url)` 让 Chromium 自行解析和跟随重定向
- Pydantic 层的 IP 校验对 Chromium 无效
- **影响**：可访问 `169.254.169.254` 等元数据端点

**S12. `CurlImpersonateEngine` 未禁用重定向 → 重定向 SSRF**
- `bypass/engines/curl_impersonate.py:89` — `req_kwargs` 未设 `allow_redirects=False`
- 该引擎是默认引擎（`engine_factory.py:18`）
- 对比 `ScraperEngine` 已显式禁用（`scraper.py:92`）
- **影响**：攻击者提交公网 URL，302 跳转到内网

**S13. Bypass 测试缺失安全关键路径**
- SSRF 校验、API key 认证、端点、缓存、并发均无测试
- 两个测试文件内容高度重复

### CI/CD 与部署

**S14. `.gitignore` 全局忽略 `package-lock.json`，edge lockfile 未追踪，CI `npm ci` 失败**
- `.gitignore:71` 无路径锚定的 `package-lock.json` 规则
- `git check-ignore edge/package-lock.json` 确认被忽略
- `.github/actions/edge-quality/action.yml:22` 执行 `npm ci`，无 lockfile 会直接失败

**S15. `web/Dockerfile` nginx 镜像以 root 运行，无 `USER` 指令**
- 全文无 `USER`，nginx master 进程以 root 运行
- 对比 `api/Dockerfile:68` 和 `bypass/Dockerfile:36` 都正确切换了非 root 用户

## 三、🟡 中等问题（精选 Top 15）

### 安全类

1. **API CORS methods/headers 全放开** — `api/nexus-server/src/app.rs:150-151` `allow_methods(Any)` + `allow_headers(Any)`
2. **API 无请求体大小限制** — `POST /api/sources`、`POST /api/sources/legado/import` 等无限制，可 OOM
3. **Bypass SSRF 存在 DNS rebinding 窗口** — `bypass/main.py:85-107`，校验与抓取间 DNS 可变
4. **Bypass API key 无 key 时完全放行，与注释矛盾** — `bypass/main.py:81-83`；且非常量时间比较
5. **Bypass 异常字符串原样回传调用方** — `curl_impersonate.py:133` 等，可能泄露内网信息
6. **Edge `Content-Length` 校验可被绕过** — `edge/shared/proxy.ts:108-109`，无 `Content-Length` 头或 `NaN` 值绕过
7. **Edge HTTP 方法未做白名单** — `edge/entry/dispatch.ts:33-44`，TRACE 等方法穿透
8. **Edge 缓存未检查 `Cache-Control`/`Authorization` 头** — `edge/shared/proxy.ts:153`
9. **Docker Compose 无网络隔离** — frontend 可横向访问 bypass（`docker-compose.yml` 无 `networks:` 段）

### 代码质量类

10. **Rust JS Worker 全局 `std::sync::Mutex` 在 async 中阻塞** — `api/nexus-engine/src/legado/selector/js.rs:135`，阻塞 tokio 线程长达 10s
11. **Rust `html_doc_cache` 全局 Mutex 串行化所有 HTML 解析** — `api/nexus-engine/src/html_doc_cache.rs:30`，多源搜索瓶颈
12. **Rust `EngineRegistry` 随机淘汰非 LRU** — `api/nexus-server/src/engine_registry.rs:44-49`
13. **Web Store 过度抽象** — `web/src/stores/` 6 个子目录 ~50 个文件，barrel 文件仅 ~30 行
14. **Web `syncManager` 模块导入时自动启动** — `web/src/services/syncManager.ts:6` 隐式副作用
15. **CI Actions 未锁定 SHA** — 全部用可变标签 `@v6`，供应链攻击面

## 六、建议优先级

### P0 — 立即修复（安全 + 可用性）

1. **S1 SSRF** — `routes/book.rs` 的 `allow_private` 改为 `false`，Legado 引擎 `fetch()` 加 IP 检查
2. **S2 JS 沙箱** — 屏蔽 `_origRequire`、`process.env`、`Function` 构造器
3. **S11/S12 Bypass SSRF** — `CurlImpersonateEngine` 加 `allow_redirects=False`；浏览器引擎 `page.goto` 前拦截重定向
4. **S14 edge lockfile** — 修改 `.gitignore` 规则，`git add -f edge/package-lock.json`
5. **S15 web root 容器** — 添加 `USER` 指令或换用 unprivileged 镜像

### P1 — 近期修复

6. **S3 HealthTracker** — 改用 `parking_lot::Mutex` 或处理 `Err`
7. **S4 SafeHtml UB** — 改用 `Arc` 替代 `Rc` 或移除 `unsafe impl Send`
8. **S6 缺少 CSP** — 在 `_headers` 添加 `Content-Security-Policy` 头
9. **S9 Edge 缓存键** — 加入 `Authorization` 头哈希
10. **S10/S13 补测试** — CORS/路由白名单/SSRF 校验/API key 认证

### P2 — 中期改进

11. CORS 收紧、请求体限制、网络隔离
12. 死代码清理、依赖位置修正
13. AGENTS.md 更新
14. Dependabot 加 github-actions 生态
15. 补充各模块单元测试和集成测试
